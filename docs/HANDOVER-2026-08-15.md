## The signing preview, rebuilt today

Reported as five things which turned out to be one: the preview was a
`max-h-[70vh] overflow-y-auto whitespace-pre-wrap` pane. Measured live on
production against a real firm template, it was **530px tall around 4168px of
content**, so a person about to sign saw about an eighth of the document
through a window that also captured the wheel.

It is now a page-turning deck of the REAL generated PDF
(`components/DocumentPdfDeck.tsx`), rasterised with the signer page's own
runtime rather than a second renderer, so the employee and the recipient look
at the same pixels from the same code. Verified live: 6 real pages against the
7 the text estimate produced, canvases painting 1738x2249 with real ink, clause
headings and page footers present, arrow keys and swipe working, pages off the
deck `inert`.

`components/DocumentSheets.tsx` (approximate text sheets) stays for the two
surfaces that hold text and cannot build a PDF: the reviewer's copy and a past
submission. It is also the deck's fallback, so a failed build leaves something
readable rather than an empty frame.

Typing 18 characters triggers **1** PDF build, measured. The debounce holds.

## Three defects I shipped today and caught by looking, not by testing

Each was green across the whole suite.

1. **Clipped text.** `h-full overflow-hidden` inside the aspect-ratio box cut a
   definition of Confidential Information off mid-sentence on page 1. Obvious
   in a screenshot, invisible to 20 passing tests.
2. **Blank pages.** `renderPageToCanvas` ran in the same effect that set the
   page list, so React had not made the canvases and `if (!canvas) continue`
   skipped every one. Six canvases at their 300x150 default inside a deck
   reporting "Page 1 of 6" that looked finished.
3. **A guard proving nothing**, for the third time in one day. It matched
   `LABEL_RE` anywhere in the file, so it passed with the signature search
   replaced by "assume the last page" and the import left sitting unused.

The through-line is in `docs/ENGINEERING_LEARNINGS.md`: **a source-reading
guard can be satisfied by its own documentation, and a green suite cannot see a
rendered page.** Strip comments before matching, require the CALL and not the
import, and render the artifact and look at it.

## Unfinished, and it does not work yet

**The approvals page falls back to text sheets in production.** `5201430a`
wires `components/SubmissionPdfDeck.tsx` so the approver sees the real PDF, and
it passes 37 tests including three mutations. On a real pending submission
(`e6ce99b4-1461-4502-a762-018c4672b7e7`) the live page rendered **0 canvases**:
the build failed and it degraded to `DocumentSheets`.

**No user-visible regression.** The fallback is the surface as it was, so an
approver sees exactly what they saw before. What is lost is the feature, plus
one failed fetch per page load.

**Root cause NOT established.** A probe posting deliberately fake ids returned
403 "You do not have access to this form", which only proves the gate rejects
garbage and says nothing about the real call. Do not treat that 403 as the
diagnosis.

What to check first, in order:
1. Instrument the real failure. `DocumentPdfDeck` swallows the error into
   `setStatus('failed')`; log the response body before deciding anything.
2. The release gate at `app/api/counsel/draft-template/pdf/route.ts:169-171`.
   Employee mode refuses the render "for anyone who could not release" a
   template that requires approval. An approver looking at a submission that is
   still PENDING approval may be exactly the case it refuses, which would make
   this design wrong rather than the wiring broken.
3. If (2) is the cause, counsel mode plus the submission's stored
   `documentText` is the fallback design, at the cost that the server no longer
   merges the firm's published template itself.
