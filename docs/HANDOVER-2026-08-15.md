## Three defects I shipped today and caught by looking, not by testing

Each was green across the whole suite.

1. **Clipped text.** `h-full overflow-hidden` inside the aspect-ratio box cut a
   definition of Confidential Information off mid-sentence on page 1. Obvious
   in a screenshot, invisible to 20 passing tests.
2. **Blank pages.** `renderPageToCanvas` ran in the same effect that set the
   page list, so React had not made the canvases and `if (!canvas) continue`
   skipped every one. Six canvases at their 300x150 default inside a deck
   reporting "Page 1 of 6" that looked finished.
3. **A guard proving nothing**, for the third time in one day. It matched
   `LABEL_RE` anywhere in the file, so it passed with the signature search
   replaced by "assume the last page" and the import left sitting unused.

The through-line is in `docs/ENGINEERING_LEARNINGS.md`: **a source-reading
guard can be satisfied by its own documentation, and a green suite cannot see a
rendered page.** Strip comments before matching, require the CALL and not the
import, and render the artifact and look at it.

## Open, asked for and not built

**1. Where does the signature land, for BOTH parties.** Reported twice:
"I don't see where the signatures go on the document for both."

What is actually true today, read rather than assumed:

- The EMPLOYEE's block is appended by `mergeTemplateDocument`
  (lib/firm-template-placeholders.ts:339) as
  `Signed: <name>` / `Date: <date>` / `Email: <email>`, and
  `findSignatureBlockLine` puts the mark above the `Signed:` line. That one
  works.
- The COUNTERPARTY's block is `buildCounterpartyBlock` (:379), which emits
  `For <name>:` / `Signature:` / `Date:` and ONLY when `counterpartyName` is
  set. With no counterparty named there is no second block at all.
- The signature blocks visible in the NDA (`THE COMPANY`, `ZINPRO
  CORPORATION`) are the TEMPLATE'S OWN TEXT, not Advottic's. They carry Name /
  Title / Address / Email and no signature rule, because the source PDF was
  flattened to text at upload.

So there are up to three different signature areas in one document and only one
of them is a real target. That is the thing to fix, and it is the same change
as the witness / second-signer request below.

Do NOT fix it by drawing a rule in the text. The comment at :375 is explicit
that placement lives in lib/signature-geometry.ts and that a second place
deciding where a signature belongs is what that module exists to prevent. That
warning was earned: the geometry previously existed in three hand-written
copies and drifted twice.

**2. Witness or second signer.** Two decisions gate the design, and both are
the owner's:
- Does a witness sign in the SAME session, or by their own emailed link?
- Is the extra signer declared on the TEMPLATE, or chosen per document?

**3. The signed screen on mobile, with the firm's logo.** `MobilePad` receives
only `handoffToken`, `signerLabel` and `documentName`. No firm name, no logo
URL, no accent. Branding has to be threaded from the handoff row through
`loadHandoffPadContext` before the screen can carry a logo. Small plumbing, but
it is plumbing, and it comes first.

**4. The oversized refusal heading**, still there. A whole sentence is being
rendered in a display `<h1>`, so a used code produces seven lines of huge serif
that also repeats itself. The fix is a dedicated refused state, and it must
honour the rule at lib/mark-handoff.ts:108 that every refusal reads identically
so a photographed screen reveals nothing about whether the code was live.
